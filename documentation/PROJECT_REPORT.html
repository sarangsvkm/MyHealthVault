1. Executive Summary & Abstract

In modern healthcare ecosystems, personal health information is heavily fragmented across physical paper records, standalone diagnostic laboratory portals, hospital electronic management systems, and proprietary wearable hardware (e.g., Apple Health, Google Fit). This fragmentation deprives both patients and clinical physicians of a comprehensive longitudinal overview of patient vitals and diagnostic history, leading to redundant tests, delayed treatments, and severe vulnerabilities during acute medical emergencies.

MyHealthVault is an enterprise-grade, cross-platform Personal Health Record (PHR) management system engineered to provide complete patient sovereignty, end-to-end data security, and uninterrupted access to lifetime medical data. Developed with a high-performance React Native (Expo SDK 54, TypeScript) mobile application and an enterprise-ready Java 21 / Spring Boot 3.5.12 REST API backed by PostgreSQL, MyHealthVault seamlessly unites hardware wearable measurements and clinical diagnostic documents.

Core Value Propositions
  • Continuous Vitals Ingestion: Hardware-level integration with Apple HealthKit and Android Health Connect for resting heart rate, step count, blood pressure, oxygen saturation ($SpO_2$), and sleep phases.
  • Secure Medical Repository: Path-traversal-proof diagnostic document storage for PDF lab reports, doctor prescriptions, and radiology scans.
  • Idempotent Deduplication: Unique compound index hashing ensuring repeat synchronizations never inflate the patient database with duplicate data points.
  • National Digital Health Ready: Dedicated architectural boundary supporting India's Ayushman Bharat Digital Mission (ABDM) and Ayushman Bharat Health Account (ABHA) consent flows.

2. Chapter 1: Introduction & Problem Statement

1.1 Background & Motivation

Healthcare delivery is undergoing a profound paradigm shift from episodic, reactive treatments to continuous, proactive, and preventive care. Everyday individuals continuously produce vital health telemetry via smartwatches and activity bands while routinely amassing diagnostic blood tests, pharmacy slips, and ultrasound imaging scans throughout their lives.

Despite the vast volume of personal health data generated, individuals face critical interoperability boundaries. An individual consulting a specialist physician rarely has immediate access to past blood panels performed at independent labs or historical resting heart rate trends captured over the preceding quarter.

1.2 Problem Statement

Existing health management solutions suffer from three fundamental bottlenecks:

  1. Physical Paper Vulnerability: Paper documents and printed thermal scan receipts rapidly deteriorate, are prone to total loss, and are completely inaccessible during remote emergencies.
  2. Walled Gardens: Apple Health is constrained to iOS, and Google Health Connect is exclusive to Android. Switching smartphones historically led to the abandonment of personal fitness and biometric history.
  3. Separation of Sensors and Clinical Records: Mainstream fitness trackers do not archive PDF pathology reports, while hospital diagnostic portals never capture continuous daily resting heart rate or sleep duration.

1.3 Project Objectives

  • Develop a responsive cross-platform mobile application supporting Android and iOS using React Native Expo and TypeScript.
  • Engineer an enterprise REST API using Java 21, Spring Boot 3.5.12, Spring Security 6, and PostgreSQL with sub-100ms response profiles.
  • Incorporate native mobile bridge adapters for Apple HealthKit and Android Health Connect to read physiological metrics directly from device daemons.
  • Build a national health integration layer compatible with the ABHA / ABDM consent framework.
  • Implement rigorous zero-trust security controls, including BCrypt password hashing, signed JWT authentication, path-traversal-proof file streaming, and immutable audit logs.

3.2 Database Schema & Data Dictionary

The relational PostgreSQL database schema is established using immutable Flyway migrations (V1__initial_schema.sql):

Table Name Primary Key Foreign Keys Purpose & Functional Description
app_user id (UUID) None Stores user account profiles, unique email addresses, and BCrypt credential hashes.
health_connection id (UUID) user_id → app_user.id Tracks connected wearable providers, status, and JSONB granted permission arrays.
health_record id (UUID) user_id → app_user.id Stores biometric readings (Heart Rate, Steps, SpO2) with numeric values and timestamps.
medical_report id (UUID) user_id → app_user.id Tracks uploaded diagnostic documents, storage keys, MIME types, and file sizes.
import_job id (UUID) user_id → app_user.id Maintains batch ingestion records, counters (total, imported, skipped, failed), and error logs.
consent_event id (UUID) user_id → app_user.id Audit records of user-granted and revoked data-sharing consents under ABDM specifications.
audit_event id (UUID) user_id → app_user.id Zero-trust security audit trail of authentication, data export, and report downloads.
Idempotency & Deduplication Engine

To prevent identical biometric entries during continuous syncing, the database enforces a partial unique constraint: 

CREATE UNIQUE INDEX uq_health_record_source
ON health_record(user_id, provider, source_record_id)
WHERE source_record_id IS NOT NULL;

Any wearable sample already ingested by unique client UUID is automatically skipped, achieving true idempotency.

4.2 Native Wearable Sensor Ingestion (TypeScript)

Mobile adapters in services/health/ handle on-device permission handshakes. Sample HealthKit ingestion adapter: 

export async function fetchAppleHealthHeartRate(startDate: Date): Promise {
  return new Promise((resolve, reject) => {
    const options = { startDate: startDate.toISOString() };
    AppleHealthKit.getHeartRateSamples(options, (err, results) => {
      if (err) return reject(err);
      const mapped = results.map(sample => ({
        provider: 'APPLE_HEALTH',
        recordType: 'HEART_RATE',
        value: sample.value,
        unit: 'bpm',
        startTime: sample.startDate,
        endTime: sample.endDate,
        sourceRecordId: sample.id
      }));
      resolve(mapped);
    });
  });
}

7. Chapter 6: Conclusion & Future Scope

MyHealthVault resolves the pervasive fragmentation of modern personal health records by offering a secure, self-sovereign, cross-platform health vault. By bridging daily lifestyle telemetry from smart wearables with diagnostic pathology files and national health identifiers (ABDM), the platform provides patients with complete control and uninterrupted accessibility over their lifetime healthcare data.

Future Roadmap (v2.0):

  • Integration of on-device LLMs (Gemini / MedLM) to parse uploaded blood tests and highlight out-of-range biomarkers automatically.
  • Longitudinal biomarker trend graphs charting multi-year cholesterol and glucose trajectories.
  • Lock-screen emergency QR code allowing first responders to retrieve blood type and allergy profiles without smartphone passcode unlocking.
